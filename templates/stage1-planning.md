# 阶段 1：计划（需求读取 → 确认 → 验证方案 → 开发计划 → 确认落盘）

## Part 0 任务恢复检查

解析需求之后、开始任何工作之前，先读 $MOD_DIR/stages/_progress.md：
存在未完成 Part → 从该处继续；不存在 → 全新开始并创建进度文件。

## Part 1 需求读取

输入两种形态：
- 自然语言需求文本：直接作为需求内容
- issue 链接：用平台 CLI 读取标题与正文（GitHub 用 gh issue view 编号，
  GitLab 用 glab issue view 编号）；CLI 不可用或读取失败 →
  请用户直接粘贴需求内容

图片/附件：仅接受用户提供的本地文件路径或可直接访问的 URL，用文件读取方式查看。

## Part 2 需求确认

向用户逐条确认你对需求的理解（功能点、边界、非目标），
确认后把结论写入 stages/stage1-part2.md。

## Part 3 验证方案

探索模块后确定：构建命令、单测命令、静态检查命令、手工验证路径。
每项写成可直接执行的命令行，写入 stages/stage1-part3.md。

## Part 4 开发计划

按里程碑拆分任务（文件级粒度），标注每步对应的验证点，写入 stages/stage1-part4.md。

## Part 5 计划确认与落盘

1. 用计划模式或列表形式向用户整体过审开发计划
2. 用户确认后，把最终计划写入 stages/stage1-part5.md
3. 更新 _progress.md：阶段 1 标记 done
4. 本阶段不回写任何外部系统；所有确认结果以本地文档为准

全部 Part 完成后才进入阶段 2。
